# 修复：电脑阵营的步兵/坦克完全不显示

## 现象

启用补丁后正常游戏，玩家看不到电脑阵营的步兵、坦克等单位；单位完全不绘制，
但游戏逻辑仍然正常（它们能攻击、摧毁玩家单位）。这是补丁引入的渲染同步问题，
不是游戏资源或地图问题。

## 根因

SAGE 引擎在每帧更新后，会调用一个“本帧是否刚开启了一个新的逻辑 tick？”的函数，
只有它返回 **yes** 时，绘制循环才会把对象状态复制到 drawable（以及运行网络速度调节、
清理等）。这个函数在 `cnc3ep1.dat` 里是：

```asm
; 0x56DABE: jmp 0x423CA2
0x423CA2  mov  eax, [0xB72AE0]     ; render FPS
0x423CA7  jmp  0x56DAC3            ; shared body
...
0x56DAC3  xor  edx, edx
0x56DAC5  div  dword [0xB72ADC]    ; eax = renderFps / logicFps (ratio)
0x56DACB  push esi
0x56DACC  push 6
0x56DACE  mov  esi, eax
0x56DAD0  pop  eax                 ; 6
0x56DAD1  cmp  eax, esi
0x56DAD3  jge  0x56DAE4            ; ratio <= 6（fps <= 90）
0x56DAD5  cdq
0x56DAD6  idiv esi                 ; 6 / ratio
0x56DAD8  xor  edx, edx
0x56DADA  pop  esi
0x56DADB  cmp  eax, [ecx+0x40]     ; phase == 6/ratio ?
0x56DADE  sete dl
0x56DAE1  mov  al, dl
0x56DAE3  ret

0x56DAE4  xor  eax, eax
0x56DAE6  cmp  dword [ecx+0x40], 1 ; phase == 1 ?
0x56DAEA  pop  esi
0x56DAEB  sete al
0x56DAEE  ret
```

补丁的批处理调度器（batches）在 tick 开始时一次运行 phase 1-3，phase 字段最终是 **3**；
120/60 FPS 时 ratio >= 6，原函数只认 **phase == 1**，所以它**永远返回 0**。
绘制循环因此从不更新 drawable，新出现的敌方单位（步兵/坦克）就不会被绘制——正是
“单位完全不显示但还能攻击”的现象。

上游 SAGE-Unlocked 对这种情况有一个 `newtick` 修复：用调度器设置一个“本帧开启了新 tick”
的标志，并把该函数替换为读取标志的 stub。但这个 1.0 版本的函数是 **split 形态**
（`jmp` thunk + 共享 body），且没有直接 `call` 引用，上游的特征扫描找不到它，
日志里只有 `missing`/没有 `newtick`，于是走了会触发上述 bug 的回退路径。

日志对比：

```
; 修复前（上游 1.9.5）
sites: ... | sched 0x570CD7 0x570DA6 | ...
; 没有 newtick

; 修复后
sites: ... | sched 0x570CD7 0x570DA6 | newtick 0x423CA2 | ...
```

## 修复

在 `ApplyPatches` 中增加对 split 形态 `isNewTick` 的识别：

```csharp
if (modeCheck.Count == 0)
{
    var splitNewTick = sites.Where(s =>
        img[s - 1 - ImageBase] == 0xA1 &&      // mov eax,[renderFps]
        img[s - 2 - ImageBase] == 0xCC &&      // int3 padding: function entry
        img[s + 4 - ImageBase] == 0xE9).ToList(); // jmp body (split form)
    if (splitNewTick.Count == 1) modeCheck = splitNewTick;
}
```

识别到 `0x423CA3` 后，上游原有的 `newtick` 逻辑会：

1. 在补丁内存写 stub `xor eax,eax / mov al,[flag] / ret`；
2. 把 `0x423CA2`（`mov eax,[fps]`）替换成 `jmp stub`；
3. 调度器 stub 在“新 tick + phase 3”时把 flag 置 1，下一次引擎 update 清零；
4. 把 `modeCheck` 从回退重定向集合中排除，避免覆盖刚写入的 `jmp` 相对偏移。

这样 `isNewTick` 在每 tick 的第一帧返回 1，drawable 每 tick 更新一次，和原版 30 FPS
的行为一致；60/120 FPS 下敌我单位都会正常绘制。

## 验证

| 项目 | 修复前（上游 1.9.5） | 修复后（本版本） |
|---|---|---|
| 日志 `newtick` | 无 | `newtick 0x423CA2` |
| `0x423CA2` | 原函数 `mov eax,[fps]` | `jmp patch+0x1140`（flag stub） |
| `isNewTick` 返回 yes | 0 次/秒（batches phase=3） | 120 FPS 约 59～61 次/秒；60 FPS 约 49 次/秒（每次 tick 的多个调用点） |
| 60 FPS 逻辑 tick | — | 15.194 次/秒（原版 15.200） |
| 120 FPS 逻辑 tick | — | 15.094～15.194 次/秒 |
| 敌方单位 | 不可见 | 正常绘制（日志验证；截图未随 GPL 包分发） |

版本：`1.9.5-kw1.0-drawfix`，DLL SHA-256 `d2c1979abd5cfcbe1b5ca7061891fc9eb47a11480adc6e333acbc60ab54545d8`。

> 说明：修复只影响 `isNewTick` 的返回值，不改变逻辑 tick 速率、逻辑帧率常量或渲染帧率；
> 60/120 的实测 tick 仍为 15.09～15.19，和原版 15.20 在采样误差内。
