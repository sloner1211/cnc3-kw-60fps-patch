## 5. 补丁制作流程（详细步骤）

### 步骤 1：工作区与目标识别

- 工具：`Get-ChildItem`、`Get-Content`、PowerShell。
- 发现游戏目录、`cnc3ep1.dat`、`cnc3ep1.exe`（EA RTS Launcher）、SkuDef、
  Core/Meta/RetailExe 的 `.big` 资源。
- 读取 `CNC3EP1_english_1.0.SkuDef`：`set-exe RetailExe\1.0\cnc3ep1.dat`。
- 判断：真正要逆向的是 `cnc3ep1.dat`，不是 1MB 的启动器。

### 步骤 2：PE 结构与可分析性

- 工具：`inspect_pe_imports`、`inspect_with_objdump`、Python 熵计算。
- 结果：
  - `MZ`/PE32/i386，入口 `0x40A245`；
  - `.text` 6,070,000 字节（VA `0x401000`），`.rdata`/`.data`/`.rsrc`；
  - 还有 `rts.ver`、`.tls`、`ars`、`est`、`artem`、`celare`、`.securom`（SecuROM 包装）；
  - `.text` 熵 6.7259、可打印率 28.8% → 代码未加密，可静态分析；
  - 导入：GDI32/USER32/KERNEL32/D3DX9_29/DSOUND/WINMM/DINPUT8 等；
    imphash `486fa4c47e09710c28553d5a99b0327e`。
- 判断：不需要脱壳；直接分析 `.text` 的 SAGE 代码。

### 步骤 3：字符串与调试信息

- 工具：PowerShell ASCII 字符串提取 + `Select-String`。
- 关键字符串：
  - 源码路径 `C:\cnc3ep_pc_qabuild\EALA-CNC3EP-BUILDCLIENT\production\code\gameengine\0.0-dev\source\GameEngine\...`
  - `UseFPSLimit`、`FramesPerSecondLimit`、`SET_FPS_LIMIT`、`Set max FPS to`
  - `W3DModelDraw`、`W3DAnim`、`Anim2D`、`TheGameLogic`、`GameClient`
- 判断：SAGE 引擎，渲染/逻辑帧率可配置，存在 `Anim2D` 2D 动画类。

### 步骤 4：IDA 自动分析与反编译

- 工具：`idat.exe -A -S dump_sites.py -L ida_dump.log cnc3ep1.dat`
- 结果：58,375 个函数；Hex-Rays 可用；数据库保存为 `work\cnc3ep1.i64`（238 MB）。
- 关键反编译：
  - 主循环 `sub_5836E5`；
  - 每帧 update `sub_570C79`；
  - 调度器 advance `0x570CD7`、exit `0x570DA6`；
  - 帧限制器 `0x583A2F`、静态初始化 `0xA010E1`；
  - 构造器 `0x7CE992`、模型步进 `0x7BA27E`；
  - `isNewTick` `0x423CA2 → 0x56DAC3`；
  - `Anim2D` `0x5D3718` / `0x5D7F7E`。

### 步骤 5：定位渲染/逻辑帧率

- 工具：Python 特征扫描。
- 特征：`B8 E8 03 00 00 33 D2 F7 35 <4字节地址> A3`（`mov eax,1000; xor edx,edx;
  div [fps]; mov [frame_ms],eax`）。
- 唯一命中：`0xA010E1`，操作数 → `0xB72AE0` = **30**（render FPS）；
  紧邻的 `0xB72ADC` = **15**（logic FPS）。
- 判断：SAGE 渲染 30 Hz、逻辑 15 Hz 两套时钟；只改渲染侧才有可能不改变游戏速度。

### 步骤 6：定位主循环与帧限制器

- 反编译 `0x5836E5`：
  - `vtable+0x14` 每帧 update；
  - `timeGetTime` + `fild [esi+0x164]`（render fps）+ `fmul gameSpeed` +
    `fdivr 1000.0` → 帧间隔；
  - `Sleep(0)` 忙等；
  - 64 帧滑动平均反推实测 FPS，夹在 `[logic, render]`。
- 参数：
  - `0xB72AE0` = 30；
  - `0xB72ADC` = 15；
  - 帧毫秒 `0xBF22F8+4`；
  - `0x583A48` 是 `_ftol` 整毫秒截断点。

### 步骤 7：定位 6 相调度器

- 反编译 `0x570C79`：
  - `[esi+0x40]` = phase（1..6）；
  - `[esi+0x44]` = renderFps / logicFps；
  - `[esi+0x48]` = interp（0..1）；
  - `[esi+0x4C]` = 新 tick 标志；
  - 满 6 后回绕，`fps/logic` 重新计算；
  - 派发走 `vtable+0x94`（本版本 `0x583577`）。
- 判断：原版 30/15 → 2 帧/tick；≥90 FPS 时引擎按“6 帧 = 1 tick” → 120 FPS 会 20 tick/s。
  必须把 tick 边界从“按帧数”改为“按真实时间”，否则游戏快 33%。

### 步骤 8：定位“新 tick”判定与 Anim2D（后来排查不可见单位用）

- `objdump` / Python：
  - `0x423CA2: mov eax,[0xB72AE0]`，`0x423CA7: jmp 0x56DAC3`；
  - body：`div [0xB72ADC]` → ratio；`ratio <= 6` 时比较 `phase == 6/ratio`，
    否则比较 `phase == 1`；
  - `0x56DABE: jmp 0x423CA2` 是调用入口（call target）。
- `Anim2D`：
  - `0x5D3718`、`0x5D7F7E` 处 `call [eax+78h]`（GameLogic::getFrame）；
  - 后续用 `0x5D3712`/`0x5D7F78` 的 `mov ecx,[0xBDD638]` 确认对象。
- 判断：`isNewTick` 的返回决定 drawable 是否更新；`Anim2D` 用渲染帧号做 30 Hz 时间轴，
  需要换算为 `ceil(frame*30/fps)`。

### 步骤 9：引入开源基线（网络审计的关键步骤）

- 工具：`web_search`、`web_fetch`、`Invoke-WebRequest`。
- 过程：
  1. 搜索到 ModDB 90 FPS Tool 与 DTF 文章；
  2. 找到 `TheeHorse/CnC-FPS-Unlocker`（后改名 SAGE-Unlocked）与 `CNCStuff/cnc3_fps_patch`；
  3. `web_fetch` 直连 GitHub 失败；改用 `api.github.com` / `raw.githubusercontent.com`；
  4. 下载 README、TECHNICAL.md、Unlocker.cs、proxy.c、build 脚本、v1.9.5 release zip。
- 判断：
  - 上游已经解决“只改渲染、不改逻辑”“30 作为特效时钟”“newtick/drawable”等坑；
  - 它的扫描器按指令形态（不是硬编码地址）工作，适合先在本版本验证；
  - 先不自己重写全部补丁，而是把上游作为基线，再针对本版本补差异。

### 步骤 10：上游补丁在本版本落地

- 工具：csc 编译/直接使用 release DLL、PowerShell 安装、SAGEUnlocked.log。
- 安装：`dinput8.dll` + `CnCFpsUnlocker.dll` + `SAGEUnlocked.ini` → `RetailExe\1.0`。
- 日志（上游 1.9.5，120）：

  ```
         tint modeltimer turrets offscreenanim

         | limiter 0x583A48 | sched 0x570CD7 0x570DA6 | models 0x7BA27E
         | particles 0x79DF11 | ...
  ```
- 判断：KW 相关核心项全部命中；`missing` 里多数是 RA3/Uprising 专用。
  `anim2d` 单独特征没命中，但 `fx` 修复已覆盖 `0x5D3718`/`0x5D7F7E`（见步骤 12）。

### 步骤 11：运行时计时验证（120/60）

- 工具：Frida（REA）。
- 钩子：
  - `0x570C79`（每帧 update）→ 渲染帧数；
  - `0x583577`（phase 派发）→ 每 tick 2 次（batches）→ `ticks = calls/2`。
- 结果：
  - 原版：30.40 FPS / 15.200 tick/s；
  - 120：118.58～118.78 FPS / 15.097～15.197 tick/s；
  - 60：59.99 FPS / 15.197 tick/s；
  - `interp` 5 秒 278 个采样、63 个不同值、0→0.97 连续变化。
- 判断：逻辑 tick 与原版差 ≤0.7%（采样/量化），游戏速度不变；渲染 120/60 达标。

### 步骤 12：Anim2D 与“缺失项”核对

- 工具：Frida 读内存 + objdump。
- 验证：
  - `0x5D3718` / `0x5D7F7E` 的 `call [eax+78h]` 被 `fx` stub（patch+0xD00）覆盖；
  - stub 字节 `8B 01 FF 50 78 6B C0 1E ...` = `getFrame*30/fps`；
  - 因此 Anim2D 已是 30 Hz 帧号，**不需要**再单独打一遍（我们曾试过一版，
    会与 fx stub 重叠造成重复换算，已放弃）。
- 判断：`missing: anim2d` 是误报，功能由 `fxframes`/`fx` 覆盖。

### 步骤 13：用户报告“敌方单位完全不显示”

- 工具：IDA/objdump 静态分析 + Frida 运行时 flag 计数。
- 现象：敌方步兵/坦克不绘制，但能攻击。
- 静态结论：
  - drawable 更新依赖 `isNewTick`；
  - 120/60 时 `ratio >= 6`，原函数只认 `phase == 1`；
  - batches 调度把 phase 停在 **3**，所以原函数永远返回 0；
  - 上游 `newtick` 特征扫描找不到这个 **split 形态**（`jmp` thunk + 共享 body，
    无直接 `call` 引用），日志里没有 `newtick`，走了会触发 bug 的回退。
- 判断：这是补丁的 drawable 同步缺失，不是游戏资源/地图问题。

### 步骤 14：drawfix 实现

- 修改 `src/Unlocker.cs` 的 `ApplyPatches`：
  - 当 `modeCheck.Count == 0` 时，在 `sites` 中找 split 形态：
    `img[s-1] == 0xA1`（`mov eax,[fps]`）、`img[s-2] == 0xCC`（int3 填充）、
    `img[s+4] == 0xE9`（jmp body）；
  - 唯一命中 `0x423CA3` 时，把它当作 `modeCheck`；
  - 上游 `newtick` 逻辑随即：
    1. 写 stub `xor eax,eax / mov al,[flag] / ret`；
    2. 把 `0x423CA2` 替换为 `jmp stub`；
    3. 调度器在“新 tick + phase 3”置 flag，下一次 update 清零；
    4. `Redirect` 集合排除 `modeCheck`，避免覆盖刚写入的 jmp 相对偏移。
- 编译：`csc /nologo /platform:x86 /optimize /target:library /r:System.Core.dll`。
- 结果：版本 `1.9.5-kw1.0-drawfix`，DLL SHA-256 `d2c1979a...`。
- 判断：只改 `isNewTick` 返回值，不动 tick 速率/逻辑常量/渲染帧率。

### 步骤 15：drawfix 运行时验证

- 日志：`sites: ... | sched 0x570CD7 0x570DA6 | newtick 0x423CA2 | ...`。
- `0x423CA2` 字节：`E9 ...` 跳到 patch+0x1140；stub 返回 flag。
- Frida flag 计数：
  - 120：`tickTrue 295 / 5s = 58.98/s`；
  - 60：`tickTrue 243 / 5s = 48.58/s`；
  - 修复前该函数返回 0。
- 逻辑 tick：
  - 120：15.094～15.194；

## 7. 判断逻辑（为什么这样选）

### 7.1 为什么不直接改 `0xB72AE0` 30→120

因为引擎在 ≥90 FPS 时按“6 帧 = 1 tick”，120 FPS 会变成 20 tick/s（快 33%）。
必须把 tick 边界改成真实时间（`timeGetTime`，66 ms），并把 6 相调度器替换为
“按到期 phase 派发 + 每帧写 interp”。

### 7.2 为什么只重定向“节奏类”的 fps 读取

SAGE 把 30 同时当“渲染帧率”和“1/30 秒时间单位”。如果全部改成 120，粒子出生时间戳
会跑到 GPU shader 时钟前面，产生满屏白/彩色闪烁。因此：
- 重定向：帧限制器、frames-per-tick、64000 实测 FPS、静态 `fild`、构造器字段等；
- 保留 30：`framesPerMs = fps*0.001`、粒子 now、shader `Time`、30 Hz 时间单位。

### 7.3 为什么用 `newtick` 而不是把 `isNewTick` 改成恒真

恒真会让 drawable/网络速度调节/清理每帧都跑，偏离原版；`newtick` 只在
“新 tick 首帧”返回 1，和原版 30 FPS 行为一致，且不改变逻辑步进顺序。

### 7.4 为什么 split 检测条件是 `A1`/`CC`/`E9`

- `s-1 == 0xA1`：`mov eax,[renderFps]`，函数第一条指令；
- `s-2 == 0xCC`：函数入口前的 int3 填充（MSVC 对齐）；
- `s+4 == 0xE9`：`jmp body`（split 形态），而不是紧接着 `33 D2`（普通 div 形态）。
唯一命中 `0x423CA3` 才启用，避免误伤其他函数。

### 7.5 为什么排除 `modeCheck` 的重定向

`newtick` 把 `0x423CA2` 的 5 个字节改成 `jmp rel32`。如果随后又把
`0x423CA3` 当 fps 操作数写入 4 字节，就会覆盖 rel32，跳转损坏。因此
`Redirect(...Except(modeCheck))`。

### 7.6 为什么 Anim2D 不再单独修

`0x5D3718`/`0x5D7F7E` 的 `call [eax+78h]` 已被 `fx` stub 覆盖，stub 做
`getFrame*30/fps`；再打一层会重复换算。验证方法：Frida 读两处 call 目标，
均为 patch+0xD00，stub 字节匹配。

### 7.7 为什么 60/120 共用同一个 DLL

补丁按 ini 的 `fps` 动态计算 `max(fps,90)`、`2*logic`、tick 长度和 `1/fps`；
同一 DLL 支持 30～240 的 15 倍数。60/120 只是 ini 不同。
